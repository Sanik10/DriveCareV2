## Архитектура и файлы

- s21_rbtree.h — общий шаблон RB-дерева: RB-память, балансировка, поиск/вставка/удаление/итераторы.
- s21_multiset.h — мультимножество на базе дерева (разрешает дубликаты).
- s21_map.h — словарь на базе дерева (уникальные ключи).
- s21_vector.h — динамический массив с ручным управлением памятью через placement new.
- s21_queue.h — очередь на односвязном списке.
- s21_stack.h — стек на односвязном списке.
- s21_containers.h — «основные» контейнеры (map, queue, stack, vector).
- s21_containersplus.h — «дополнительные» контейнеры (multiset, и потенциально array).
- tests/*.cc — юнит-тесты для vector/queue/stack/map/multiset.

Основная идея: ассоциативные контейнеры разделяют одну базу — RB-дерево — с параметрами:
- способ извлечения ключа из value,
- компаратор,
- флаг AllowDuplicates для set/multiset/unique-структур.

## Общие соглашения

- Исключения вместо UB в «опасных» местах:
  - Разыменование end() итератора, ++end(), --begin() — std::out_of_range.
  - Пустые контейнеры (front/back/top/pop/pop_back) — std::out_of_range.
- Итераторы для ассоциативных контейнеров — двунаправленные и поддерживают --end() → последний элемент.
- Семантика эквивалентности ключей: через Compare (компаратор), не через operator==. Два ключа эквивалентны, если !(a < b) && !(b < a).

## s21_rbtree.h — базовое RB-дерево

### Параметры шаблона и типы

```cpp
template <typename Value, typename Key, typename KeyOfValue,
          typename Compare, bool AllowDuplicates>
class rb_tree { ... };
```

- Value — тип значения в узле.
- Key — тип ключа, по которому упорядочиваем.
- KeyOfValue — функтор извлечения ключа из Value (identity для multiset, select1st для map).
- Compare — строгий слабый порядок (по умолчанию std::less<Key>).
- AllowDuplicates — флаг дубликатов (true для multiset, false для map/set).

Полезные вспомогательные функторы:
- `detail::identity<V>` — возвращает `V` как есть.
- `detail::select1st<std::pair<K,V>>` — возвращает `pair.first`.

### Узел, корень и sentry (`nil_`)

```cpp
struct Node {
  value_type value;
  Color color;        // RED/BLACK
  Node* parent;
  Node* left;
  Node* right;

  explicit Node(const value_type& v) : value(v), color(RED), ... {}
  explicit Node(value_type&& v)      : value(std::move(v)), color(RED), ... {}
};
Node* root_;  // корень дерева
Node* nil_;   // специальный «лист» (sentinel)
size_type size_;
Compare comp_;
KeyOfValue key_of_;
```

- `nil_` — один объект-«лист» для дерева:
  - цвет — BLACK,
  - `parent/left/right` указывают на `nil_`,
  - `root_` у пустого дерева указывает на `nil_`.
- Конструктор дерева выделяет `nil_` через `new Node(value_type{})`. Это требует `Value` быть default-constructible. Возможное улучшение ниже.

### RB-инварианты

1) Узел красный или черный.
2) Корень — черный.
3) Все листья (nil_) — черные.
4) У красного узла оба потомка — черные.
5) Любой путь от узла до всех листьев содержит одинаковое количество черных узлов.

Поддерживаются поворотами и «поднятием/перекрашиванием» при вставке/удалении.

### Итераторы

Итераторы двунаправленные и хранят:
- `current_` — текущий узел,
- `root_` — корень дерева (чтобы уметь `--end()`),
- `nil_` — sentinel.

Операции:
- Разыменование `*it`/`it->` — бросает, если `current_ == nil_`.
- `++it` — переход к следующему (минимум в правом поддереве, иначе поднимаемся к первому «левому предку»).
- `--it`:
  - если `it == end()` (то есть `current_ == nil_`) → перейти к максимальному элементу `maximum(root_)`;
  - иначе — к предшественнику (максимум в левом поддереве, либо спускаемся по правым ребрам к первому «правому предку»).
- Сравнение — по адресу `current_` и sentinel `nil_` (гарантирует, что итераторы из разных деревьев не сравниваются как равные).

`begin()` — минимальный узел, `end()` — `nil_`.

### Вставка (insert)

Упрощенно:
1) Идем вниз от корня, используя компаратор:
   - `comp_(k, x)` — идем влево,
   - `comp_(x, k)` — идем вправо,
   - иначе ключ эквивалентен.
2) Если `AllowDuplicates == false` и нашли эквивалентный ключ — возвращаем {iterator на существующий узел, false}, узел не вставляем.
   Если `AllowDuplicates == true`, при равенстве ключей продолжаем спуск вправо — чтобы дубликаты шли вправо и корректно считались bound-операторами.
3) Создаем узел `z`, вешаем его как `left/right` к найденному родителю.
4) `z->color = RED`, затем `insert_fixup(z)` для восстановления RB-инвариантов:
   - случаи: дядя красный — перекрашивание и подъем;
   - дядя черный — поворот+перекрашивание.
5) Корень окрашиваем в BLACK.
6) size_++.

Сложность: O(log N).

### Удаление (erase)

`erase(iterator)` удаляет точный узел, `erase_key(key)` — удаляет все дубликаты при `AllowDuplicates`, или 0/1 при unique.

Алгоритм:
1) Классический RB-delete: если у узла 0/1 «настоящих» детей — «перестановка» через `transplant`. Если двое детей — ищем минимум в правом поддереве, переставляем, копируем цвет, и переразвешиваем связи.
2) Удаляем физически один узел `delete z`.
3) Если удаляли черный узел — `delete_fixup(x)` восстанавливает инварианты:
   - набор случаев с «братом» `w` (если красный — один поворот и перекрашивание; иначе учитываем цвета детей `w->left/right`, возможны 2 поворота).
4) size_--.

Итераторы на другие узлы сохраняются (адреса узлов не меняются, меняются только связи). Инвалидируются только итераторы на удаляемые узлы.

Сложность: O(log N).

### Поиск и границы

- `find(key)` — бинарный поиск по дереву, O(log N).
- `lower_bound(key)` — первый узел, не меньший key.
- `upper_bound(key)` — первый узел, строго больший key.
- `equal_range(key)` — пара {lower_bound(key), upper_bound(key)}.
- `count(key)`:
  - для multiset — количество эквивалентных ключей (итерируем от `lower_bound` пока ключи эквивалентны);
  - для unique — 0/1.
- `contains(key)` — `find(key) != end()`.

### merge

`merge(other)` переносит элементы из другого дерева:
- unique-дерево (map/set): дубликаты не переносятся, уникальные — переносятся и удаляются из `other`.
- multi-дерево (multiset): переносятся все элементы; `other` становится пустым.

Реализация — безопасная итерация с пост-удалением по одному элементу:
```cpp
for (auto it = other.begin(); it != other.end();) {
  auto res = insert(*it);
  if (res.second || AllowDuplicates) { auto to_erase = it++; other.erase(to_erase); }
  else { ++it; }
}
```

Сложность: O(M log(N+M)).

### Повороты и fixup

- `left_rotate(x)`: правый ребенок x (`y`) становится на место x, x — левым ребенком y. Обновляем связи родитель/дети.
- `right_rotate(x)`: симметрично.
- `insert_fixup(z)`: стандартный набор случаев с красным родителем/дядей.
- `delete_fixup(x)`: стандартные 4 случая с «братом» w.

Обе процедуры поддерживают инварианты RB-дерева.

### Исключения, валидность итераторов

- Разыменование `end()` и переход за границы итерации — выбрасывают std::out_of_range (в STL это UB; так безопаснее и согласовано с тестами).
- Вставка и повороты не инвалидируют итераторы на существующие узлы; инвалидируется только итератор на удаляемый узел.
- Конструктор `nil_` — `new Node(value_type{})` требует `Value` быть default-constructible. См. «Улучшения».

### Улучшения/варианты

- Убрать требование default-constructible у `Value` для `nil_`:
  - использовать `std::aligned_storage` и не конструировать `value` у `nil_`, аккуратно избегать обращений к `value` внутри операций с nil.
- Альтернативные деревья:
  - AVL — более строгий баланс, быстрая выборка, больше поворотов.
  - Treap — рандомизированный баланс, проще код, вероятностные гарантии.
  - B-деревья — настраиваемая степень, хороши для дисков/кэшей.
  - Для STL-совместимости RB-подобные деревья — стандартный выбор.

## s21::multiset

Объявление:
```cpp
template <typename Key, typename Compare = std::less<Key>>
class multiset {
  using tree_type = detail::rb_tree<Key, Key, detail::identity<Key>, Compare, true>;
  tree_type tree_;
  ...
};
```

- Значение = ключ, `identity` извлекает ключ напрямую, дубликаты разрешены.
- Методы — тонкие обертки над `tree_`:
  - вставки `insert` возвращают `iterator` (булево для multiset всегда true в insert_many),
  - `erase(key)` удаляет все вхождения, возвращает число удаленных,
  - `count`, `find`, `contains`, `lower_bound`, `upper_bound`, `equal_range`,
  - `merge` переносит все элементы, включая дубликаты,
  - итераторы поддерживают `--end()`.
- Сложность:
  - все операции поиска/вставки/удаления — O(log N),
  - `count` на диапазоне дубликатов — O(k + log N).

## s21::map

Объявление:
```cpp
template <typename Key, typename T, typename Compare = std::less<Key>>
class map {
  using value_type = std::pair<const Key, T>;
  using key_of_value = detail::select1st<value_type>;
  using tree_type = detail::rb_tree<value_type, Key, key_of_value, Compare, false>;
  tree_type tree_;
  ...
};
```

- `value_type` — `pair<const Key, T>` как в std::map (ключ константный).
- Ключ извлекается через `select1st`.
- Уникальные ключи (`AllowDuplicates=false`).

Ключевые методы:
- `at(const key&)` — ссылка на `mapped_type`, если нет — std::out_of_range.
- `operator[](const key&)` — возвращает ссылку на значение:
  - при отсутствии ключа — вставляет `{key, T{}}` и возвращает ссылку на `second`.
  - требование: `T` — default-constructible (как и в std::map для operator[]).
- `insert(...)` — перегрузки: по паре/по паре rvalue/по (key,value), возвращают `{iterator, bool}`.
- `insert_or_assign(key, value)` — при наличии ключа заменяет `mapped`, возвращает `{iter, false}`; иначе вставляет `{iter, true}`.
- `erase(iterator)`/`erase(key)`.
- `find/contains/lower_bound/upper_bound/equal_range`.
- `merge(map&)` — переносит только уникальные элементы.
- `insert_many(...)` — вектор результатов `{iterator, bool}`.

Сложность:
- логарифмические для всех базовых операций.

Итераторы:
- двунаправленные, поддерживают `--end()`, стабильны при вставке, инвалидируются при удалении соответствующего узла.

## vector

Память:
- Буфер как «сырая» память: `new char[capacity * sizeof(T)]`, далее `reinterpret_cast<T*>` + placement new для конструирования элементов.
- Деструкторы вызываются вручную (`data_[i].~T()`), за освобождение буфера — `delete[]` на исходный `char*`.

Итераторы:
- Непосредственно указатели (`T*`), поддерживают арифметику, сравнения.
- Отличие от STL: разность итераторов возвращает `size_t` (у STL — signed `ptrdiff_t`). Тестами ожидается `size_t`.

Модификаторы:
- `reserve` — аллоцирует новый буфер, перемещает/перекладывает элементы.
- `shrink_to_fit` — уменьшает capacity до size.
- `resize` — конструирует/уничтожает «хвост» как нужно.
- `assign` — версии по числу/иниц-листу/итераторам.
- `insert` — одиночный, множественный; сдвиги делаются с конца, элементы перемещаются.
- `erase` — диапазон: уничтожаем элементы и сдвигаем хвост.
- `emplace`, `emplace_back`, `insert_many`, `insert_many_back`.

Исключения:
- `at`/`front/back` на пустом — std::out_of_range.
- `pop_back` на пустом — std::out_of_range.

Инвалидация итераторов:
- При увеличении capacity — все итераторы инвалидируются.
- При вставке/удалении внутри текущего буфера — итераторы на элементы после точки вставки/удаления могут стать невалидными.

## queue / stack

Структура:
- Односвязный список: `Node { T data; Node* next; }`.
- queue хранит `front_node_` и `back_node_`, stack — `top_node_`.
- Итераторы — однонаправленные (`++`), без `--`.

Исключения:
- Пустые операции (`front`, `back`, `top`, `pop`) — std::out_of_range.

Модификаторы:
- queue: `push` в хвост, `pop` с головы.
- stack: `push` на вершину, `pop` с вершины.
- Оба имеют `insert_many_back` (Part 3).

## FAQ

В: Почему используется sentinel `nil_`?
- Упрощает корректность: все пустые ссылки валидны, цвет `BLACK`, не нужно везде проверять на nullptr, проще fixup.

В: Почему итераторы хранят `root_` и `nil_`?
- Чтобы корректно поддержать `--end()` и ходить по дереву без доступа к контейнеру извне.

В: Что с эквивалентностью ключей?
- Эквивалентность через `Compare`: `a` и `b` эквивалентны, если `!(a<b) && !(b<a)`. Это важно для типов без operator==, но с компаратором.

В: Стабильность итераторов при вставке?
- Да, адреса узлов не меняются (перестраиваются ссылки и цвета). Инвалидируется только итератор на удаляемый элемент.

В: Чем RB лучше AVL здесь?
- Баланс «достаточно хороший», fewer rotations в среднем, исторически выбран для std::map/set. AVL даёт лучшую высоту, но чаще вращается.

В: Почему `value_type{}` у `nil_` и что если `Value` недефолтируемый?
- Текущая реализация требует default-constructible. Для полной совместимости можно хранить `value` в `union/std::aligned_storage` и не конструировать его у `nil_`. В проекте это не критично (используются int/string/пары).

В: Чем `insert_or_assign` отличается от `insert`?
- `insert` не перезаписывает существующий ключ; `insert_or_assign` — перезаписывает `mapped` и возвращает `{it, false}`.

В: Почему в vector `operator-(iterator)` возвращает `size_t`, а не `ptrdiff_t`?
- Так проще под текущие тесты. В STL — `ptrdiff_t`. Если потребуется — можно поменять.

В: Какие исключения бросают итераторы?
- Разыменование `end()` или переход за границы (++ на end, -- на begin) — std::out_of_range.

В: `merge` у multiset переносит все дубликаты?
- Да, multiset — мультиножество: все элементы переносятся, а у unique-контейнеров — только уникальные.
