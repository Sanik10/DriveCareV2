## Общие вопросы

— Зачем общий RB‑tree?
- Чтобы не дублировать логику для map/multiset (и потенциально set). Меняем только: способ извлечения ключа, компаратор, флаг дубликатов.

— Какие контейнеры построены на этом дереве?
- s21::map<Key, T> (уникальные ключи) и s21::multiset<Key> (дубликаты разрешены).

— Поддерживаются ли методы из Part 3 (insert_many)?
- Да. В map/multiset — vector<pair<iterator,bool>>, в queue/stack — insert_many_back.

## Красно‑черное дерево (s21_rbtree.h)

— Что параметризуется?
- Value — тип значения в узле.
- Key — тип ключа.
- KeyOfValue — функтор для извлечения ключа из Value (identity или select1st).
- Compare — строгий слабый порядок (std::less).
- AllowDuplicates — разрешены ли дубликаты.

— Что такое sentinel nil_ и зачем он?
- Один общий «пустой» узел (BLACK). Упрощает код: нет nullptr, проще обход/фиксация. Пустое дерево: root_ = nil_. У nil_ поля parent/left/right указывают на него же.

— Какие инварианты RB‑дерева соблюдаются?
- Корень чёрный; nil_ чёрный; у красного узла дети чёрные; одинаковое число чёрных узлов по всем путям; каждый узел красный/чёрный.

— Как реализованы итераторы и почему умеют --end()?
- Итератор хранит current_, а также root_ и nil_. Это позволяет:
  - --end() → перейти на максимальный элемент дерева;
  - ++max → end(). Разыменование end() кидает исключение.

— Почему итераторы бросают исключения?
- В проекте в «опасных» местах выбраны исключения вместо UB (например, разыменование end(), ++end(), --begin()).

— Как работает вставка при AllowDuplicates=false/true?
- Если ключ эквивалентный найден:
  - unique (map): возвращаем итератор на существующий узел, bool=false.
  - multi (multiset): продолжаем спуск вправо и вставляем новый узел (дубликаты справа). Это гарантирует корректные lower/upper_bound.

— Как реализованы lower_bound/upper_bound/equal_range?
- lower_bound — первый узел, не меньший key.
- upper_bound — первый узел, строго больший key.
- equal_range — пара {lower_bound, upper_bound}. Для multiset покрывает диапазон дубликатов.

— Что делает merge?
- map (unique): переносит только уникальные элементы, дубликаты остаются в источнике.
- multiset (multi): переносит все элементы, источник пустеет.
- Сложность: O(M log(N+M)).

— Какие повороты используются?
- Классические left_rotate/right_rotate. insert_fixup/delete_fixup — стандартные случаи (красный дядя → перекрасить и поднять; иначе повороты+перекраски).

— Можно ли модифицировать ключ в map?
- Нет. value_type = pair<const Key, T>. Ключ константный.

— Стабильны ли итераторы?
- Вставка/балансировка не инвалидирует итераторы на другие узлы. Инвалидируется только итератор на удаляемый узел. После erase он невалиден.

— Почему в move-конструкторе у «other» создаётся новый nil_?
- Чтобы «other» оставался валидным пустым деревом (root_=nil_, nil_ корректен), и его деструктор был безопасен.

— Можно ли передать свой компаратор?
- Да: Compare в шаблоне контейнера.

— Что с эквивалентностью ключей?
- Эквивалентность через Compare: !(a<b) && !(b<a). operator== не требуется.

## Ассоциативные контейнеры поверх дерева

— Чем map отличается от multiset в этой реализации?
- map — уникальные ключи, value_type = pair<const Key, T>, operator[] и at для доступа к mapped.
- multiset — дубликаты разрешены, value_type = Key, count может быть >1, erase(key) удаляет все вхождения.

— Чем at отличается от operator[] в map?
- at(key) — бросает std::out_of_range при отсутствии ключа.
- operator[](key) — вставляет {key, T{}} при отсутствии и возвращает ссылку на mapped. mapped_type должен быть default-constructible.

— Что делает insert_or_assign в map?
- Если ключ есть: присваивает новое значение mapped, возвращает {it, false}.
- Если нет: вставляет новую пару, возвращает {it, true}.

— Что возвращают insert в map и multiset?
- map: pair<iterator,bool>.
- multiset: iterator (как в std::multiset). В нашем insert_many для multiset bool всегда true — по требованиям Part 3 (единый интерфейс).

— Что возвращает erase(key)?
- map: 0 или 1.
- multiset: количество удалённых элементов (все дубликаты).

— Поддерживает ли итератор --end()?
- Да, у обоих.

Примеры:
```cpp
s21::map<int,std::string> m{{1,"a"},{2,"b"}};
m[3] = "c";         // вставит {3,"c"}
auto it = m.find(2);
--m.end();          // итератор на максимальный ключ

s21::multiset<int> ms{1,2,2,3};
auto [l,u] = ms.equal_range(2); // диапазон всех «2»
ms.erase(2);                     // удалит оба «2»
```

## vector

— Как хранится память?
- Сырая память через `new char[cap*sizeof(T)]`, далее placement new для конструирования элементов, явные вызовы деструкторов. Освобождение исходного char‑буфера в деструкторе.

— Когда перевыделяется память?
- При вставке/добавлении, если size == capacity. Политика роста: x2 (или до нужного размера).

— Какие гарантии по исключениям у reserve/shrink_to_fit?
- При T с noexcept‑перемещением — сильная гарантия. Если перемещение может бросать, поведение имеет базовую гарантию (на практике мы используем типы, у которых move noexcept — int, std::string и т. п.).

— Почему разность итераторов возвращает size_t, а не ptrdiff_t?
- Под тесты проекта. В STL это ptrdiff_t. Можно заменить при необходимости.

— Чем insert_many отличается от emplace?
- insert_many принимает готовые элементы и вставляет их последовательно.
- emplace конструирует элемент на месте из аргументов.

## queue / stack

— Почему у них есть итераторы? В STL их нет.
- По ТЗ требуются итераторы. Реализованы однонаправленные (++), без --.

— Что делают push/pop?
- queue: push в конец, pop с головы.
- stack: push на вершину, pop с вершины.

— Что если pop на пустом?
- Бросаем std::out_of_range (безопасно и согласовано с тестами; в STL это UB).

— Зачем insert_many_back?
- Part 3: массовая вставка в конец.

## Исключения и гарантии

— Где бросаются исключения?
- Итераторы: разыменование end(), ++end(), --begin().
- vector: at/front/back/pop_back на пустом.
- queue/stack: front/back/top/pop на пустом.
- map::at — при отсутствии ключа.

— Какие гарантии по дереву при исключениях?
- new Node(...) может бросить — в таком случае структура не изменяется (сильная гарантия для вставки).
- Компаратор, если бросит, поведение как у любой пользовательской функции — структура остаётся валидной, но операция не завершена.

— Какая гарантия у vector::reserve?
- Сильная при noexcept move T. Иначе — базовая (в проекте достаточно).

## Производительность и инвалидация итераторов

— Сложность основных операций:
- map/multiset: поиск/вставка/удаление — O(log N).
- merge — O(M log (N+M)).
- vector: доступ O(1), insert/erase — амортизированно O(N), reserve/shrink — O(N).
- queue/stack: все операции — O(1) амортиз.

— Инвалидация итераторов:
- map/multiset: вставка не инвалидирует итераторы; удаление инвалидирует итератор на удалённый узел.
- vector: при перевыделении инвалидируются все; при вставках/удалениях внутри буфера — итераторы после позиции вставки/удаления могут стать невалидными.
- queue/stack: pop инвалидирует итератор на удалённый узел.

## Диагностика и типичные кейсы

— Почему equal_range/upper_bound/lower_bound на multiset «видят» дубли?
- Дубликаты вставляются вправо от эквивалентного ключа. Это обеспечивает непрерывный диапазон [lower, upper) всех дубликатов.

— Что делает erase(end()) в multiset/map?
- Ничего (проверка на sentinel): безопасный no‑op.

— Можно ли сменить компаратор под кастомный порядок?
- Да, шаблонный параметр Compare в map/multiset.

— Что если хочется map без требования default‑constructible у T при operator[]?
- Стандартная семантика operator[] требует default‑construction. Используйте `at` или `insert_or_assign`, чтобы не требовать T{}.

— Можно ли сделать дерево без default‑constructible Value?
- Да, через aligned_storage и «неинициализированный» value у nil_. В этой версии достаточно дефолтных типов (int/string/pair).

— Безопасно ли ++ на итераторе в конце?
- Нет, бросит std::out_of_range. Корректно: проверять it != end() перед разыменованием/инкрементом.

— Как работать с ranges‑for?
```cpp
s21::map<int,std::string> m{{1,"a"},{2,"b"}};
for (auto& [k, v] : m) { /* ... */ }

s21::multiset<int> ms{1,2,2,3};
for (int x : ms) { /* ... */ }
```

— Как безопасно сливать два контейнера?
```cpp
s21::map<int,std::string> a{{1,"x"}}, b{{1,"y"},{2,"z"}};
a.merge(b); // получим {1:"x",2:"z"}; b останется с {1:"y"} (дубль)
```

— Примеры insert_many:
```cpp
s21::map<int,std::string> m;
auto res = m.insert_many(std::pair<const int,std::string>(1,"a"),
                         std::pair<const int,std::string>(1,"b"),
                         std::pair<const int,std::string>(2,"c"));
// res[0].second==true, res[1].second==false (дубль), res[2].second==true

s21::multiset<int> ms;
auto r2 = ms.insert_many(1,1,2);
// все bool == true
