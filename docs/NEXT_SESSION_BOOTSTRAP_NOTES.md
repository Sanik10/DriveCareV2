Аудит (универсально, без кода)
Проведи аудит модуля и периферии. На этом шаге код/патчи не присылай.
- Покрой: ФЗ РФ (152, 242, 402, 54, 161, PCI при необходимости), безопасность (auth/RBAC/XSS/SQLi/CSRF/headers/cookies/PII/аудит/ретеншн), качество кода (архитектура, типизация, DTO/валидация, транзакции, перфоманс).
- Дай список конкретных изменений, приоритеты, краткую мотивацию. После подтверждения — попрошу патч.

Правки — Backend (unified diff)
Если у тебя нет точного актуального содержимого файлов — НЕ присылай diff, а сначала запроси файлы (см. шаблон “Запрос файлов” ниже).
Иначе сгенерируй ОДИН или несколько валидных unified diff патч‑блоков:

- Каждый патч — отдельный блок ```diff (или ```patch). Вне блоков — только краткие комментарии без кода.
- Пути строго от корня: a/apps/backend/... и b/apps/backend/...
- В каждом хунке:
  - Все неизменённые строки начинаются с одним пробелом.
  - Числа в заголовке @@ -L1,N +L2,M @@ соответствуют реальному числу строк в хунке (N = кол-во ‘ ’ + ‘-’; M = ‘ ’ + ‘+’).
  - Контекст ≥ 3 строки, без “...”.
- Новый файл: --- /dev/null и +++ b/<path> (можно new file mode 100644).
- Удаление файла: --- a/<path> и +++ /dev/null (можно deleted file mode).
- Переименование — как удаление+добавление или валидный rename diff.
- Можно несколько diff‑блоков в одном ответе.

Правки — Frontend (unified diff)
Правила те же, пути: a/apps/frontend/... и b/apps/frontend/...

Запрос файлов (когда контент неизвестен)
Если у тебя нет точного текущего содержимого для генерации валидного diff, сначала верни список нужных файлов:

```
NEED FILES (точные текущие версии):
- apps/backend/src/.../work-schedules-business.service.ts
- apps/backend/src/.../work-schedules-data.service.ts
- ...
Причина: нужен точный контекст, иначе unified diff может быть невалидным.
```

После того как я пришлю файлы — генерируй патч по правилам выше.

Мини‑памятка для ИИ
- Не гадай содержимое — запроси файлы, если их нет.
- Один ответ — только diff‑блоки (или path‑blocks). Никаких других код‑блоков.
- В хунках: пробел для контекста, корректные счетчики, ≥3 строки контекста, без “...”.
- Backend: apps/backend/...; Frontend: apps/frontend/...
- Если сомневаешься — используй path‑blocks.

Почему это важно
- Валидный diff требует точного исходника. Если модель его не видит — почти гарантированы “corrupt patch”.
- Схема “NEED FILES → diff” или прямой “path‑blocks” решает проблему на 100%.
