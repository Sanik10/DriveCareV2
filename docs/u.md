# Tariffs (тарифы) — контракт API и UI-спецификация

Обновлено: текущей сессией

Цель: быстрый референс для фронтенда/дизайна. Публичный каталог тарифов скрывает внутренние метрики и “сырой” JSON — в UI показываем только «красивые» плашки, переключатели и понятные подписи.

---

## Эндпоинты

Публичные (без метрик):
- GET /api/v1/tariffs — листинг (read-only; без метрик подписчиков)
- GET /api/v1/tariffs/active — только активные тарифы
- GET /api/v1/tariffs/popular?limit=6 — популярные (по активности, но в ответе без метрик)
- GET /api/v1/tariffs/compare?ids=uuid1,uuid2 — сравнение
- GET /api/v1/tariffs/:id — детали тарифа

Backoffice (platform admin only):
- GET /api/v1/tariffs/admin — листинг с расширенными фильтрами и метриками
  - Параметры: search, isActive, minPrice, maxPrice, minActiveSubscribers, minTotalSubscribers, page, limit, sortField, sortOrder
- POST /api/v1/tariffs — создать тариф
- PATCH /api/v1/tariffs/:id — обновить тариф
- PATCH /api/v1/tariffs/:id/status?isActive=true|false — включить/выключить тариф
- DELETE /api/v1/tariffs/:id — удалить (запрещено, если есть активные/исторические подписки)

RBAC: superadmin, platform_admin — для CRUD/админ-листинга. Публичные GET открыты (с учётом глобальных guard’ов).

---

## Ответ (TariffResponseDto)

Всегда (публично и в админке):
- id: string (uuid)
- name: string — название тарифа
- description?: string — краткое описание
- priceMonthly: number — цена/месяц (руб.)
- priceYearly: number — цена/год (руб.)
- yearlyDiscount?: number — скидка за год, %
- maxUsers?: number | null — лимит пользователей (null = безлимит)
- maxCustomers?: number | null — лимит клиентов (null = безлимит)
- maxVehicles?: number | null — лимит ТС (null = безлимит)
- maxOrders?: number | null — лимит заказов (null = безлимит)
- features?: object — функциональные/маркетинговые флаги (см. ниже)
- isActive: boolean — активность тарифа (виден ли в витрине)
- createdAt: string (ISO)
- updatedAt: string (ISO)
- isRecommended?: boolean — вспомогательный флаг (вычисляется из features и/или названия)

Только для админ-листинга (/tariffs/admin):
- activeSubscribers?: number — активные подписчики (уникальные компании сейчас)
- totalSubscribers?: number — уникальные компании, когда-либо покупали тариф
- subscriptionsCount?: number — совместимость (то же, что activeSubscribers)

Примечание: публичные ответы не содержат метрик подписчиков.

## Создание тарифа (CreateTariffDto)

Body (JSON):
- name: string — обязательно (1..100 символов)
- description?: string — до 1000 символов
- priceMonthly: number — >= 0
- priceYearly: number — >= 0; не больше (priceMonthly × 12) и должна давать скидку не меньше 1%
- maxUsers?: number — > 0 (опустить поле = безлимит)
- maxCustomers?: number — > 0 (опустить = безлимит)
- maxVehicles?: number — > 0 (опустить = безлимит)
- maxOrders?: number — > 0 (опустить = безлимит)
- features?: object — см. «Features» ниже
- isActive?: boolean — по умолчанию true

Бизнес-валидации:
- priceYearly ≤ priceMonthly × 12
- Минимальная скидка за год: 1% (можно поднять в константах)
- Лимиты > 0 (или не указаны для безлимита)
- Название уникально (case-insensitive)
- features — только разрешённые ключи

---

## Обновление тарифа (UpdateTariffDto)

Любые поля из CreateTariffDto — опциональны. Те же ограничения/валидации. Можно передать isActive (или использовать PATCH /:id/status).

---

## Features (объект возможностей)

Разрешённые ключи (тип boolean):
- reports — Отчёты
- analytics — Аналитика
- api_access — Доступ к API
- priority_support — Приоритетная поддержка
- custom_fields — Пользовательские поля
- integrations — Интеграции
- advanced_reports — Расширенные отчёты
- white_label — White-label/брендинг

Маркетинговые ключи:
- recommended: boolean — «Рекомендовать на витрине»
- badge: string — один из: popular | best_value | new | sale | recommended | hot
- tags: string[] — набор тегов (до 50 шт., каждый ≤ 40 символов)
- highlight: boolean — витринная подсветка/акцент
- shelf_position: number — позиция на витрине (целое 0..9999)

Поддерживаются алиасы (если приходят из старых интеграций):
- labels → tags
- display_rank → shelf_position

На бэкенде строки "true"/"false"/"1"/"0" нормализуются к boolean.

## Рекомендованный UI (без «сырого» JSON)

Для формы создания/редактирования:
- Переключатели (галочки/слайдеры):
  - Отчёты (reports)
  - Аналитика (analytics)
  - Доступ к API (api_access)
  - Приоритетная поддержка (priority_support)
  - Пользовательские поля (custom_fields)
  - Интеграции (integrations)
  - Расширенные отчёты (advanced_reports)
  - White-label (white_label)
- Маркетинг:
  - Рекомендовать на витрине (recommended) — чекбокс
  - Бейдж (badge) — select:
    - — Нет —
    - Популярный (popular)
    - Лучшее предложение (best_value)
    - Новинка (new)
    - Скидка (sale)
    - Рекомендован (recommended)
    - Хит (hot)
  - Теги — input: «через запятую» (сохранить в tags[])
  - Подсветка на витрине (highlight) — чекбокс
  - Позиция на витрине (0..9999) — numeric (shelf_position)
- Лимиты (пусто = безлимит):
  - Макс. пользователи
  - Макс. клиенты
  - Макс. ТС
  - Макс. заказы

Тексты/подсказки (tooltips), короткие:
- Отчёты: «Создание и экспорт отчётов»
- Аналитика: «Дашборды и графики»
- Доступ к API: «Интеграции и собственные приложения»
- Приоритетная поддержка: «Быстрые ответы и выделенная линия»
- Пользовательские поля: «Кастомные поля и атрибуты»
- Интеграции: «Подключение сторонних сервисов»
- Расширенные отчёты: «Сводные и сегментация»
- White-label: «Брендинг: домен/логотип/цвета»
- Рекомендовать на витрине: «Подсветить тариф как рекомендованный»
- Бейдж: «Маркер на карточке тарифа»
- Позиция на витрине: «Чем меньше число — тем выше в списке»

Важно: на публичных страницах не показывать “features” как JSON — только визуальные чек-листы/бейджи.

## Примеры

Создание «Стандарт»:

```json
POST /api/v1/tariffs
{
  "name": "Стандарт",
  "description": "Оптимальный для небольших и средних автосервисов",
  "priceMonthly": 2500,
  "priceYearly": 25000,
  "maxUsers": 10,
  "maxCustomers": 200,
  "maxVehicles": 500,
  "features": {
    "reports": true,
    "analytics": false,
    "api_access": false,
    "priority_support": false,
    "custom_fields": true,
    "integrations": true,
    "recommended": true,
    "badge": "best_value",
    "tags": ["выгодный", "старт бизнеса"],
    "highlight": true,
    "shelf_position": 10
  },
  "isActive": true
}
```

Обновление — сделать «Популярным» и увеличить лимит пользователей:
```json
PATCH /api/v1/tariffs/:id
{
  "features": { "badge": "popular" },
  "maxUsers": 20
}
```

Админ-листинг с метриками и сортировкой по активным подписчикам:
```
GET /api/v1/tariffs/admin?minActiveSubscribers=1&sortField=activeSubscribers&sortOrder=desc&page=1&limit=20
```

## Фильтры/сортировка (админ-листинг)

Фильтры:
- search — по name/description (ILIKE)
- isActive — true/false
- minPrice / maxPrice — по priceMonthly
- minActiveSubscribers — уникальные активные компании (сейчас)
- minTotalSubscribers — уникальные компании за всё время

Сортировка:
- sortField: name | priceMonthly | priceYearly | createdAt | activeSubscribers | totalSubscribers
- sortOrder: asc | desc

---

## Поведение удаления/статуса

- Нельзя удалить активный тариф — сначала деактивируйте.
- Нельзя удалить тариф, если на нём есть активные или исторические подписки (сохранность истории). Рекомендуется оставлять деактивированным.
- isActive=false — тариф скрыт из витрины, текущие подписки продолжают работать до конца периода.

---

## Нюансы

- Безлимитные лимиты: просто не отправляйте поле (UI: оставьте инпут пустым).
- Скидка за год: по умолчанию ≥1%; иначе вернём 400 с ошибкой валидации.
- Публичные GET-эндпоинты не возвращают метрики (active/totalSubscribers).
- isRecommended в ответе — вычисляемый флаг (features.recommended || badge ∈ {recommended, best_value} || эвристика по названию).
