DRIVECARE DESIGN SYSTEM v1.1

Философия продукта

DriveCare — это не бухгалтерская система и не корпоративный ERP-комбайн.

DriveCare — инструмент управления автосервисом.

Пользователь должен чувствовать:

* контроль над бизнесом
* порядок в данных
* скорость работы
* современный подход

Интерфейс не должен выглядеть перегруженным.

Если элемент не помогает работать с данными — его не должно быть.

⸻

Визуальный характер

DriveCare сочетает:

* тёмную тему
* неоновые акценты
* строгие формы
* минимализм

Вдохновение:

* Linear
* Stripe Dashboard
* Vercel Dashboard
* Raycast
* Notion (по структуре)

Не использовать:

* стеклянность ради стеклянности
* тяжёлые тени
* кислотные цвета
* сложные анимации

⸻

Правило 80/20

80% интерфейса:

* карточки
* таблицы
* формы
* списки

20% интерфейса:

* красивые акценты
* градиенты
* визуальные эффекты

Красота должна подчёркивать данные, а не конкурировать с ними.

⸻

Структура страниц (Layout)

Все страницы Dashboard собираются по одному паттерну.

Базовый каркас страницы:

AppLayout
→ container (px-lg py-xl)
→ NavigationHeader
→ (опционально) StatsGrid
→ PageFiltersCard
→ PageContentCard
→ PaginationControls (если есть страницы)

Запрещено собирать страницу “по-своему”, если её можно собрать из стандартных блоков.

⸻

Навигация

Все страницы обязаны иметь одинаковую структуру заголовка.

Структура:

[Иконка]

Название страницы

Описание страницы

Действия

⸻

Пример:

🚗 Автомобили

Управление транспортными средствами клиентов

[Фильтр] [Экспорт] [+ Автомобиль]

⸻

Правило “Назад” (Back)

Кнопка “Назад/К списку” не должна жить в Actions.

Возврат на список делается через NavigationHeader:

backHref
backLabel (пример: “К заказам”, “К клиентам”, “К автомобилям”)

Кнопка “Назад” должна быть рядом с “Домой / Дашборд” (в навигационной строке заголовка).

⸻

Отступы

Используется единая шкала.

XS = 4

SM = 8

MD = 12

LG = 16

XL = 24

XXL = 32

SECTION = 48

Запрещены случайные значения.

⸻

Скругления и иконки (единый “почерк”)

Скругления:

* базовый радиус: rounded-md
* не использовать большие “пилюли” и “3xl” без необходимости

Иконки:

* иконки в кнопках: 16px (w-4 h-4)
* иконка в NavigationHeader: 20px (w-5 h-5)

⸻

Карточки

Карточка — основной строительный блок системы.

Любая карточка состоит из:

Header

Body

Footer (опционально)

⸻

Карточки бывают только 3 видов.

Статистическая карточка

Информационная карточка

Карточка сущности

⸻

Запрещено придумывать новые типы карточек.

⸻

Информационные карточки (Section Cards)

На Detail Pages карточки-секции (“Финансы”, “Автомобиль”, “Владелец”, “История”) считаются Информационными карточками.

Это не новый тип карточки — это стандартный контейнер секции с данными.

⸻

Статистические карточки

Используются:

* Dashboard
* Заказы
* Клиенты
* Автомобили
* Счета

Структура:

Иконка

Название

Значение

Изменение показателя

⸻

Высота всегда одинаковая.

⸻

Карточки сущностей

Используются:

* Клиенты
* Автомобили
* Сотрудники

Структура:

Название

Статус

Ключевая информация

Быстрые действия

⸻

Пользователь должен понимать карточку за 3 секунды.

Если требуется больше времени — карточка перегружена.

⸻

Формы

Формы должны ощущаться одинаково во всей системе.

Структура:

Название поля

Поле ввода

Описание ошибки

⸻

Не использовать формы без подписей.

Placeholder не заменяет Label.

⸻

Select / Textarea (единые правила)

Select и Textarea — такие же поля формы, как Input.

Обязательные правила:

* всегда иметь Label (или sr-only label в фильтрах)
* высота Select = 40px (h-10), строгая рамка и отступы по шкале
* ошибки отображаются по той же логике, что и у Input

⸻

Обязательные поля

Всегда отмечаются:

Пример:

Телефон *

Email *

VIN *

⸻

Кнопки

В системе существует только 4 типа кнопок.

Primary

Главное действие страницы

Secondary

Вторичное действие

Ghost

Незначительное действие

Danger

Удаление и опасные операции

⸻

На странице может быть только одна Primary-кнопка.

Если Primary-кнопок две — пользователь теряет фокус.

Уточнение для Empty States:

Если на странице уже есть Primary в заголовке (например “+ Создать”), то в Empty State действие должно быть Secondary (или Ghost).

Primary в Empty State допустима только если на странице нет Primary-действия в заголовке.

⸻

Статусы

Статусы во всей системе используют одинаковую логику.

Активен → зелёный

Ожидание → жёлтый

В работе → синий

Ошибка → красный

Черновик → серый

⸻

Единые токены статусов (строго 5)

Все доменные статусы (заказ, запись, счет и т.д.) маппятся на 5 системных токенов:

active (green)

pending (yellow)

progress (blue)

error (red)

draft (gray)

Один и тот же статус не может менять цвет в разных разделах.

⸻

Таблицы

Таблицы должны выглядеть одинаково.

Высота строки:

фиксированная

⸻

Строка содержит:

Основную информацию

↓

Вторичную информацию

↓

Действия

⸻

Запрещены таблицы с 15+ колонками.

Если колонок становится слишком много — нужен Detail Screen.

⸻

Detail Pages

Самые важные страницы продукта.

Каждая Detail Page должна отвечать на вопросы:

Кто?

Что?

Когда?

Сколько?

Что делать дальше?

⸻

Если страница не отвечает на эти вопросы — структура плохая.

⸻

Timeline

Timeline используется для:

* клиентов
* автомобилей
* заказов
* сотрудников

Структура записи:

Иконка

Событие

Описание

Дата

⸻

Все таймлайны выглядят одинаково.

⸻

Empty States

Пустое состояние должно не просто сообщать об отсутствии данных.

Оно должно подсказывать следующий шаг.

Плохо:

Нет автомобилей.

Хорошо:

У вас пока нет автомобилей.

Добавьте первое транспортное средство клиента.

[Добавить автомобиль]

⸻

Модалки

Максимальная ширина ограничена.

Не превращать модалки в полноценные страницы.

Если форма занимает больше одного экрана:

использовать отдельную страницу.

⸻

Горячие клавиши (ускорение работы)

Если применимо к разделу, используем единые сочетания:

Cmd/Ctrl + K — фокус на поиск

Cmd/Ctrl + N — создать сущность раздела

Cmd/Ctrl + Enter — подтвердить действие в модалке (создание)

Esc — закрыть модалку

⸻

Анимации

Анимации должны быть быстрыми.

Цель:

обратная связь

а не демонстрация красоты.

Разрешено:

Hover

Fade

Scale

Slide

Запрещено:

Сложные цепочки

Долгие переходы

Прыгающие элементы

⸻

Проверка новой страницы

Перед созданием страницы ответить на вопросы:

1. Какой Layout используется?
2. Какие готовые компоненты используются?
3. Есть ли аналогичная страница в системе?
4. Можно ли собрать страницу из существующих блоков?

Если ответ “нет” более чем на один вопрос — дизайн нужно пересмотреть.
